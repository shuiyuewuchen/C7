# C7 AI 使用日志（AI_LOG）

> 记录周期：2026-11-21
> 记录人：赵心皓
> 目标：让 AI 使用「可追溯、可复现、可改进」，避免「一句话出稿直接交」

---

## 一、整体工作流设计（8 阶段）

```
① 选题分析 → ② 受众定位 → ③ 大纲设计 → ④ 分段初稿
     → ⑤ 改稿去味 → ⑥ 标题生成/投票 → ⑦ 排版转换 → ⑧ 数据复盘
```

**关键设计**：每一阶段的产出都是下一阶段的输入，且**每一阶段都有人工决策点**。AI 负责生成与展开，我负责方向、真实素材与质量把关。

| 阶段 | 我的角色 | AI 的角色 | 人工决策点 |
|---|---|---|---|
| 选题 | 提供 C1–C6 真实经历清单 | 扩展成 10 个选题并评分 | 选出 3 个成系列 |
| 大纲 | 指定目标读者与结构 | 生成 6 段式大纲 | 删掉「工具测评」段 |
| 初稿 | 提供具体数字/工具/踩坑 | 分段扩写 | 逐段核对事实 |
| 改稿 | 指出空洞套话 | 口语化改写 | 保留第一人称语气 |
| 标题 | 组织小范围投票 | 生成 10 个候选并标注公式 | 选定 3 个主标题 |
| 排版 | 定义样式规范 | 生成并迭代转换脚本 | 检查 3 次渲染结果 |
| 数据 | 定义追踪口径 | 生成看板与曲线 | 逐项核对数字 |
| 复盘 | 提供失败经验 | 结构化 AAR | 确认改进方案可执行 |

## 二、逐轮 Prompt 记录（含迭代）

### 轮次 1：选题生成（v1 → v2）

**v1 Prompt**
```
根据 Elite20 的 7 个挑战，帮我生成 10 个公众号选题。
```
**v1 问题**：输出 10 个标题都很泛，例如「我的 AI 学习心得」，没有受众和角度，无法直接用。

**v2 Prompt（优化点：加受众 + 加约束 + 加输出格式）**
```
背景：我在 Elite20 完成了 C1 翻译、C4 技能、C5 GitHub、C6 Web App。
目标读者：对 AI 感兴趣、但自认「技术小白」的大学生。
请生成 10 个公众号选题，要求：
1. 每个选题必须来自我的一项真实经历
2. 用「数字 + 结果」或「反常识」或「第一人称」公式
3. 输出表格：选题 | 来源挑战 | 目标读者收获 | 预估吸引力(1-5)
4. 不要出现「学习心得」「心得体会」这类空泛词

```
**v2 输出**：10 个选题，我选中 3 个组成「普通人用 AI 做出东西的 90 天」系列（翻译 / 技能 / Web App），因为它们覆盖「输入 → 工具 → 产品」的完整链条，且每项都有可量化的结果。

> **迭代经验**：选题 Prompt 必须给出「素材清单」和「禁用词」，否则 AI 会退回通用套路。

---

### 轮次 2：大纲设计（v1 → v2）

**v1 Prompt**
```
帮我写一篇关于 AI 翻译的公众号文章大纲。
```
**v1 问题**：大纲是教科书式结构（定义→方法→总结），没有故事，读者不会点进来。

**v2 Prompt（优化点：指定叙事结构 + 指定开头方式）**
```
写一篇公众号文章的大纲，目标读者是「英语一般、想快速消化英文资料」的大学生。
素材：我把一份 142 页、12 万字的斯坦福讲义用 AI 在 3 小时内译完，
      踩过术语漂移、公式损坏、长段落漏译三个坑。
要求：
1. 严格按 6 段结构：痛点故事 / 为什么重要 / 具体过程 / 结果 / 踩坑 / 读者行动
2. 开头 3 句话内必须出现一个具体数字
3. 「具体过程」拆成 4-5 个可编号的步骤
4. 每一步标注需要什么配图
5. 结尾设计一个开放式互动问题

```
**v2 输出**：形成五步流水线大纲，直接成为文章骨架。

> **迭代经验**：给 AI 大纲任务时，「结构」和「开头钩子」必须分开明确要求，否则它会自动省略钩子。

---

### 轮次 3：初稿分段生成（v1 → v2 → v3）

**v1 Prompt**
```
按这个大纲写一篇 2000 字的公众号文章。
```
**v1 问题**：约 1200 字，且每个段落都像总结报告，没有「我」的语气。

**v2 Prompt（优化点：分段生成 + 强制第一人称 + 强制细节）**
```
按大纲写「具体过程」这一段，600 字。
要求：
1. 全程第一人称「我」，不要用「我们」「笔者」
2. 每一步必须出现至少一个具体数字或具体工具名
3. 每段不超过 3 行（手机阅读）
4. 重要结论加粗
5. 不要写「首先/其次/最后」这类连接词，用自然过渡

```
**v2 问题**：细节有了，但出现「极大地提升了效率」这类空洞套话 4 处。

**v3 Prompt（优化点：增加禁用词清单 + 要求替换成具体数字）**
```
把上面这段改写：
1. 删除「极大地提升」「显著提升」「赋能」「助力」等空泛副词
2. 凡出现「提升效率」的地方，替换成具体数字（如从 X 降到 Y）
3. 保留所有具体工具名、提示词原文、踩坑细节
4. 保持口语化，像在群里跟同学讲话

```
**v3 输出**：成为三篇文章正文的最终写法依据。

> **迭代经验**：**改稿比初稿更重要**。一次「去空话 + 换数字」的针对性改稿，效果远好于反复重写。

---

### 轮次 4：标题生成与筛选

**Prompt**
```
给《3 小时译完 12 万字斯坦福讲义》这篇文章起 10 个公众号标题。
要求：
1. 覆盖 5 种公式：数字+结果 / 反常识 / 过程+结果 / 痛点+方案 / 第一人称
2. 每个不超过 25 字
3. 标注每个标题使用的公式
4. 不要标题党（不要「震惊」「不看后悔」）

```
**输出**：10 个候选，全部收录进文章文件的「备选标题」表格。
**筛选方式**：发到 8 人小群投票，得票最高的 1 个作为主标题；其余保留用于后续 A/B 测试。

> **迭代经验**：让 AI 标注「使用的公式」，能快速识别重复套路，避免 10 个标题其实只有 2 种写法。

### 轮次 5：排版脚本（v1 → v2 → v3）

**v1**：让 AI 直接输出带 `<style>` 标签的 HTML。
**问题**：公众号编辑器会剥离 `<style>`，粘贴后样式全丢。

**v2**：要求全部样式内联。
**问题**：中文渲染正常，但表格在手机上会撑破屏幕。

**v3 Prompt（优化点：加移动端约束）**
```
写一个 Markdown 转微信公众号 HTML 的 Python 脚本：
1. 所有样式必须内联（公众号会剥离 <style>）
2. 正文 15px / 行高 1.75 / 段间距 18px
3. 配色不超过 3 种：#333333 / #2563EB / #F4F7FF
4. 表格外层加 overflow-x:auto，避免手机端撑破
5. 代码块用 pre-wrap，长行自动换行
6. 无 JS、无外部资源，纯标准库实现

```
**v3 输出**：`md2wechat.py`，三篇文章一键转换。这同时是 C4 联动的可复用工作流组件。

---

### 轮次 6：数据看板渲染（v1 → v2）

**v1**：用 Swift 的 NSBezierPath 绘图。
**问题**：文字正常，但所有色块都没渲染——命令行环境没有 NSGraphicsContext。

**v2 修复**：改用 CoreGraphics 直接 `addPath` + `fillPath`。
**结果**：看板、曲线、三张文章配图全部正常渲染。

> **迭代经验**：AI 生成的代码在 GUI 框架下经常有「本地能跑、命令行不渲染」的隐蔽问题。**必须实际运行并肉眼验证**，不能只看代码。

## 三、Prompt 优化规律总结

| 优化手段 | 解决的问题 | 出现轮次 |
|---|---|---|
| 给素材清单（具体数字/工具/经历） | 输出空洞、无真实细节 | 1、2、3 |
| 给禁用词清单 | 「赋能/助力/极大提升」套话 | 3 |
| 指定输出格式（表格/编号/字数） | 输出不可直接用 | 1、4 |
| 分段生成而非一次成稿 | 长文质量衰减、字数不足 | 3 |
| 要求标注推理依据（公式/颜色/口径） | 便于快速筛选与复用 | 4、5 |
| 人工实际运行并肉眼验证 | 代码「看起来对但跑不出」 | 6 |

## 四、AI 使用边界（重要）

- AI 负责：选题扩展、结构生成、语言润色、标题候选、格式转换、图表渲染
- 我负责：**真实经历与数字**、事实核对、方向取舍、质量把关、发布运营
- 文中所有具体数字（页数、字数、用时、使用次数）为**写作示例素材**，正式发布前需替换为本人真实记录
- 未使用 AI 生成任何虚假的平台后台数据；演示看板已在图面显著标注 `DEMO DATA`
